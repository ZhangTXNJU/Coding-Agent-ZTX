# Feature Specification: Coding Agent (编程智能体)

**Feature Branch**: `001-coding-agent`

**Created**: 2026-08-29

**Status**: Draft

**Input**: User description: "阅读 requirement.md 文档的项目要求。理解这个项目的目标。评估项目的难度以及你打算使用怎样的技术来实现这个 coding agent。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完成一个端到端的编程任务 (Priority: P1)

开发者向 agent 用自然语言下达一个编程任务（例如"在现有项目里新增一个命令行参数并补充对应测试"），agent 自主地浏览代码库、修改文件、运行命令验证结果，最终交付一个可工作的改动。

**Why this priority**: 这是 coding agent 的核心价值——替代开发者手动完成"读代码 → 改代码 → 验证"的循环，是整个项目的立身之本。

**Independent Test**: 对一个示例仓库下达一个明确的小任务，观察 agent 是否在不人工干预的情况下产出正确的文件改动，并给出可验证的结果。

**Acceptance Scenarios**:

1. **Given** 一个包含若干源文件的本地项目，**When** 用户下达"新增一个功能"的自然语言任务，**Then** agent 能够读取相关文件、定位需要修改的位置、写入改动，并运行验证命令确认结果。
2. **Given** 一个明确的编程任务，**When** agent 运行过程中命令执行失败（如测试未通过），**Then** agent 读取失败输出并据此调整后续操作，而不是直接中止或无限重试。
3. **Given** 任务已完成的信号（模型明确表示完成），**When** agent 检测到该信号，**Then** agent 停止循环并向用户汇报完成结果与所做改动。

---

### User Story 2 - 与模型进行多轮对话并管理上下文 (Priority: P1)

agent 与 LLM 进行多轮交互，维护完整的对话历史；当历史过长时自动压缩/裁剪，避免超出模型的上下文上限。

**Why this priority**: 上下文管理是题目要求"必须自行编写"的核心逻辑之一，也是 agent 能否处理真实规模项目（大量文件、长历史）的关键。

**Independent Test**: 让 agent 执行一个需要多轮工具调用、产生较长历史的任务，验证其历史随轮次增长且最终任务仍能完成；再构造一个超长历史场景，验证其能裁剪旧内容而不崩溃。

**Acceptance Scenarios**:

1. **Given** 一次多轮交互，**When** 每一轮产生新的工具调用与结果，**Then** agent 将新消息追加到对话历史并发送给模型。
2. **Given** 对话历史长度逼近模型上限，**When** agent 准备发送下一轮请求，**Then** agent 自动对历史进行裁剪或摘要，保证请求不超出上下文上限。
3. **Given** 一次历史压缩发生，**When** 后续交互继续，**Then** agent 仍保留足够信息以完成当前任务。

---

### User Story 3 - 在本地安全地执行命令与读写文件 (Priority: P2)

agent 具备一组本地工具（读文件、写文件、执行 shell 命令等），并能安全、可控地执行它们，将结果反馈给模型。

**Why this priority**: 工具的定义与本地执行同样是题目要求自写的核心逻辑；本地命令执行是 coding agent 区别于"纯聊天机器人"的关键能力。

**Independent Test**: 通过一个受控的本地环境（如临时目录），验证 agent 能读取文件内容、写入新文件、执行命令并捕获标准输出/错误输出。

**Acceptance Scenarios**:

1. **Given** 用户要求读取某个文件，**When** agent 调用读文件工具，**Then** 该文件内容被返回并纳入上下文。
2. **Given** 用户要求执行一条命令，**When** agent 调用命令执行工具，**Then** 命令在本地执行，其标准输出与退出码被返回。
3. **Given** 一条命令超时或产生错误，**When** agent 执行该命令，**Then** agent 收到错误信息并继续处理，而不是挂起或静默失败。

---

### User Story 4 - 可靠地解析模型输出并终止循环 (Priority: P2)

agent 正确解析模型的工具调用输出，并具备明确的循环终止条件（任务完成、达到最大步数、连续错误等）。

**Why this priority**: 输出解析与终止条件是题目明确要求自写的逻辑；没有可靠的终止条件，agent 会陷入无限循环或过早退出。

**Independent Test**: 验证 agent 能区分"模型请求工具调用"与"模型给出最终回答"两种输出；构造一个模型持续出错的场景，验证 agent 在达到阈值后停止并汇报。

**Acceptance Scenarios**:

1. **Given** 模型返回工具调用，**When** agent 解析该输出，**Then** agent 正确识别工具名与参数并执行。
2. **Given** 模型返回最终回答（不再请求工具），**When** agent 解析该输出，**Then** agent 将回答返回给用户并结束循环。
3. **Given** 循环达到配置的最大步数或连续失败阈值，**When** 该条件满足，**Then** agent 停止并明确告知用户原因。

---

### User Story 5 - 凭据与配置的安全管理 (Priority: P3)

API key 等凭据一律通过环境变量或未入库的配置文件提供，绝不写入仓库、README 或演示视频。

**Why this priority**: 这是题目明确要求的合规项，泄漏凭据会直接导致失分，属硬性约束。

**Independent Test**: 检查仓库全部提交历史、README 与配置样例中是否存在明文凭据；验证 agent 仅从环境变量读取凭据。

**Acceptance Scenarios**:

1. **Given** 环境变量中存在 API key，**When** agent 启动，**Then** agent 从环境变量读取凭据并可正常调用模型。
2. **Given** 仓库被推送至公开平台，**When** 检查全部提交历史与文件内容，**Then** 不存在任何明文凭据。
3. **Given** 用户未提供凭据，**When** agent 启动，**Then** agent 给出清晰提示并要求提供凭据，而不是崩溃或泄露默认值。

---

### User Story 6 - 演示友好的交互与安全可控执行 (Priority: P3)

开发者通过终端界面与 agent 交互，实时看到模型的流式输出、每一步工具调用及其结果；当 agent 准备执行破坏性命令时要求确认；任务中断后可恢复继续。

**Why this priority**: 这是"可用、可演示"的体验层，直接决定演示视频的观感；核心闭环（P1/P2）已由前述故事覆盖。

**Independent Test**: 运行一个多步任务，观察终端是否实时渲染进展、破坏性命令是否弹出确认、中断后用续跑能力能否恢复。

**Acceptance Scenarios**:

1. **Given** agent 执行任务，**When** 模型产生输出与工具调用，**Then** 终端实时流式显示进展，而非等全部结束后一次性输出。
2. **Given** agent 准备执行一条破坏性命令，**When** 该命令被识别为危险，**Then** agent 暂停并请求用户确认后才执行。
3. **Given** 一次任务被中断，**When** 用户重启并请求续跑，**Then** agent 恢复到中断前状态并继续。

---

### User Story 7 - 自定义 Skill 加载 (Priority: P3)

开发者可定义自己的 skill（类似 Claude Code 的 SKILL.md：名称、描述、触发条件、指令正文与可选脚本/参考文件），agent 在需要时按需加载并注入上下文，从而扩展特定领域能力（如代码审查、特定框架约定、PDF 处理等）。

**Why this priority**: 这是"像 Claude Code"的关键差异化能力，但属增强项，核心闭环（P1/P2）稳定后再做。

**Independent Test**: 创建一个示例 skill（含 SKILL.md 元数据与指令），验证 agent 能列出可用 skill、在相关任务中触发加载并将指令注入上下文。

**Acceptance Scenarios**:

1. **Given** 项目里存在若干 SKILL.md，**When** agent 启动或需要时，**Then** agent 能扫描并列出可用 skill 的名称与描述。
2. **Given** 用户任务与某 skill 的触发条件相关，**When** agent 决定使用该 skill，**Then** agent 读取其指令正文并注入上下文，据此行动。
3. **Given** 一个 skill 引用了参考文件或脚本，**When** agent 加载该 skill，**Then** agent 能按需读取这些附加内容。

---

### Edge Cases

- 模型返回格式损坏（无法解析的 JSON / 缺少字段）时，agent 如何处理？（应重试或安全降级，而非崩溃）
- 命令执行超时（如死循环、等待输入的命令）时，agent 如何避免挂起？
- 模型在单轮中请求多个工具，或请求一个不存在的工具时，agent 如何响应？
- 目标文件不存在、无写权限、或写入路径超出工作目录时，agent 如何安全地失败？
- 对话历史超过模型上下文上限时，agent 如何裁剪而不丢失关键信息？
- 网络/API 调用失败（限流、超时、5xx）时，agent 如何重试与降级？
- 用户中途中断（Ctrl-C）时，agent 如何优雅退出而不留下脏状态？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Agent MUST 接受用户以自然语言下达的编程任务，并记录任务目标。
- **FR-002**: Agent MUST 与所选大语言模型进行多轮对话，维护并管理完整的对话历史与上下文。
- **FR-003**: Agent MUST 提供至少"读取文件"与"写入/修改文件"两类本地文件工具，并能返回文件内容与操作结果。
- **FR-004**: Agent MUST 提供本地命令执行工具，能运行 shell 命令并捕获标准输出、错误输出与退出状态。
- **FR-005**: Agent MUST 自行解析模型输出，区分"请求工具调用"与"给出最终回答"两类结果。
- **FR-006**: Agent MUST 将工具执行结果反馈给模型，形成"模型决策 → 本地执行 → 结果回传"的闭环循环。
- **FR-007**: Agent MUST 具备明确的循环终止条件，至少包括：任务完成信号、最大迭代步数、连续失败阈值。
- **FR-008**: Agent MUST 对模型输出解析失败、工具执行失败、API 调用失败等错误进行妥善处理，避免崩溃或无限循环。
- **FR-009**: Agent MUST 在对话历史逼近模型上下文上限时进行自动裁剪或压缩。
- **FR-010**: Agent MUST 仅通过环境变量或未入库的配置文件读取 API 凭据，任何凭据不得出现在仓库、README 或演示中。
- **FR-011**: Agent MUST 允许用户配置模型端点、模型名称与凭据来源（通过配置或环境变量）。
- **FR-012**: Agent MUST 提供与用户交互的入口（命令行界面），可接收任务并展示执行过程与最终结果。
- **FR-013**: Agent MUST 将本地工具执行限制在受控的工作目录范围内，避免无意的越界写操作。
- **FR-014**: Agent MUST 支持基于行范围或差异的精准文件编辑，使改动可审阅、可回退，而非只能整文件覆盖。
- **FR-015**: Agent MUST 提供代码检索能力（按文件名模式与内容正则搜索），并能在任务开始时了解项目目录结构。
- **FR-016**: Agent MUST 对破坏性命令（如删除、强制覆盖、推送到远端等）在执行前请求用户确认。
- **FR-017**: Agent MUST 支持会话状态与对话历史的持久化，允许任务中断后恢复继续执行。
- **FR-018**: Agent MUST 以实时流式方式展示模型输出与工具执行进展，确保演示过程清晰可读。
- **FR-019**: Agent MAY 支持加载自定义 skill（含元数据、指令正文与可选资源），并在相关任务中按需注入上下文。

### Key Entities *(include if feature involves data)*

- **Task（任务）**: 用户下达的自然语言编程目标；包含目标描述、工作目录、执行状态。
- **Message（消息）**: 对话中的单条记录，属于用户、模型或工具结果三类角色之一；按时间顺序构成对话历史。
- **Tool（工具）**: 一个可被模型调用的能力，含名称、参数定义（schema）与本地执行逻辑（如读文件、写文件、执行命令）。
- **Tool Call / Result（工具调用与结果）**: 模型发起的一次工具调用请求及其对应的本地执行结果。
- **Configuration（配置）**: 模型端点、模型名、凭据来源、终止阈值等运行参数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Agent 能在无人工干预的情况下，完成一个代表性的端到端编程任务（新增功能或修复缺陷），并产出可验证的正确改动。
- **SC-002**: Agent 在正常完成任务时，能在配置的最大步数上限内结束循环，且不出现无限循环或过早退出。
- **SC-003**: Agent 对单次工具调用（读文件、执行命令）的本地执行与结果回传在数秒内完成，使用户可实时观察进展。
- **SC-004**: 面对命令执行失败或模型输出异常，Agent 能在有限次重试内恢复或安全停止，而不是崩溃或挂起。
- **SC-005**: 仓库全部提交历史、README 与演示视频中零明文凭据泄漏（100% 通过凭据扫描检查）。
- **SC-006**: 一位不熟悉实现细节的评审者能够仅凭 README 与 2 分钟视频，理解 agent 的功能与核心实现思路。

## Assumptions

- 目标模型支持原生的函数/工具调用（tool calling）接口，并通过 OpenAI 兼容网关访问；具体模型厂商与名称由实现者选定，可在运行时配置。
- Agent 以命令行工具形态运行在开发者的本地机器（macOS / Linux）上，v1 不涉及多用户服务端或 Web 界面。
- 目标形态是"可用、可演示"的单体 CLI 产品（对标 Claude Code / Codex / OpenCode 的体验），而非最小演示脚本；子 agent 委派与 MCP 接入作为"更强"的加分能力，可在核心闭环稳定后增量实现。
- 工具集以"读文件 / 写文件 / diff 式编辑 / 执行命令 / 列出目录 / 代码搜索"为核心，确保能完成真实规模的编程任务。
- 凭据默认从环境变量读取；配置文件样例只含占位符，实际凭据文件加入 `.gitignore` 且不提交。
- 安全边界以"限定工作目录 + 命令超时 + 危险命令确认"为默认策略，不作为多租户沙箱强度处理。
- 设计参考：learn-claude-code（教学范式）以及 OpenCode、Codex CLI（开源源码），仅作架构借鉴，不直接封装或复制其产品界面。
